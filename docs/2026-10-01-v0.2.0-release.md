# v0.2.0 发布说明

发布日期：2026-10-01

`v0.2.0` 是一个 TUN 策略路由正确性与健壮性发布，重点是让 bypass 规则跟随路由表变化自动对账、把裸主机路由纳入 bypass 集合，并让两个服务实例不可能再互相拆掉对方的 TUN 设备。

## 重点变化

- 策略路由 bypass 规则对账（自愈）
  - bypass 目标此前只在建立 TUN 的那一刻对主路由表做一次快照，之后不做任何对账：核心若早于 DHCP / Docker / VPN 路由启动，局域网网段就永远不会进入 bypass 集合。
  - 现在每 `30s` 比对“主路由表应有的 bypass 集合”与“内核已装集合”，发现缺失或过期即在 `coreOpMu` 内重建。
  - 覆盖场景：开机早于网络、DHCP 续租、Docker 网桥起停、VPN 接口上下线、切换网络。
  - 核心未运行、正在启动、TUN 关闭或处于 hijack（默认路由接管）模式时自动跳过；日志按漂移签名去重，重建失败告警 5 分钟节流。

- 裸主机路由不再被丢弃
  - `ip route show table main` 中的点对点 / WireGuard / VPN 主机路由（例如 `10.88.0.1 dev wg0 scope link`）此前会被 `netip.ParsePrefix` 静默拒绝并丢弃。
  - 现在统一归一化为 `/32`（IPv6 为 `/128`）后保留，这类路由不再被 TUN 吞掉。

- 单实例数据目录锁
  - `launcher.RunServer` 启动时对数据目录取 `flock` 排他锁；第二个服务进程在绑定端口、触碰网络之前就报错退出。
  - 锁由内核在进程退出时释放，崩溃不会留下死锁；锁文件记录持有者 pid，错误信息会直接指出是谁占着。

- TUN 拆除前确认没有其他实例
  - `clearTunRouting` / `cleanupStaleTunInterface` 会先扫描 `/proc`：只要还有另一个 v2rayE 后端实例存活，就整体跳过拆除（不删 `xraye0`、不清规则、不改写共享的还原意图）。
  - 进程识别只认可 `backend-api` 或带 `--server` 的 `v2raye`：统一二进制同时也是 TUI 客户端，裸 `v2raye` 进程不会被误判为 TUN 的拥有者。

- 出站网卡绑定校验
  - `resolveOutboundInterfaceForSockopt` 在 TUN 关闭时同样校验 `outboundInterface` 是否存在：不存在的设备不会再写进生成配置，避免所有出站连接绑到一块坏网卡。
  - TUN 开启时仍以当前默认路由出接口为准。

- 诊断与清理安全
  - 新增两条告警：bypass 规则与实际路由表不同步（30s 内自动重建）、出站绑定网卡与当前默认路由不一致（需重启核心重绑）。
  - 规则清理增加属主校验：只删除 `from all` 且 `lookup main` / `lookup 20230` 的自家规则，不再按 `10000-10999` 优先级区间无差别删除其他工具安装的规则。
  - `fib table does not exist`（IPv6 无默认路由时的常见输出）不再作为清理错误上报。

- 运维脚本
  - `tun-health-check.sh` 检测到 `v2raye-server.service` 处于 active 时改用 `POST /api/core/restart` 验证核心自恢复，不再执行 dev 流程启动第二个实例；dev 分支改为后台启动，脚本不再阻塞。
  - `stop-dev.sh` 在 systemd 单元 active 时给出明确告警，提示先 `systemctl stop v2raye-server`。

## 对用户的直接影响

- 局域网访问（尤其是 ICMP / UDP / 组播）在核心早于网络启动的场景下不再失效，且无需手动重启核心。
- Docker 网段、VPN 对端等后加入的路由会自动进入 bypass 集合，不再被 TUN 吞掉。
- 不会再出现“启动第二个实例导致在跑的实例 TUN 被反复删除”的事故（此前实测一次事故中 systemd 空转重启 139 次）。
- 关闭 TUN 后不会因为配置里残留的网卡名而全量断网。
- 版本升级不破坏现有数据：`config.json` 中残留的 `outboundInterface` 会被安全忽略（不再写入生成配置）。

## 发布验证

本次版本发布前已通过以下验证：

```bash
cd backend-go && go build ./...
cd backend-go && go vet ./...
cd backend-go && go test -race ./...
```

线上验证（本机 systemd 部署）：

- `tun-health-check.sh` 全部通过（16 项），包含 API 重启后的 TUN 接管恢复。
- 手动删除一条 bypass 规则后，30s 内被对账机制自动补回。
- 同数据目录手动启动第二个实例被锁拒绝，运行中的实例与 TUN 状态零影响。
