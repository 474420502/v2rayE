# v0.1.5 发布说明

发布日期：2026-08-10

`v0.1.5` 是一个后端稳定性和可靠性发布，重点是把存储层的读写可靠性、核心生命周期并发安全，以及订阅的自动化维护一起收敛。

## 重点变化

- 存储层缓存 + 原子写
  - profiles / subscriptions / config / routing / state 五个数据文件的读写全部改为内存缓存，读多写少的热路径（如状态轮询）不再每次访问磁盘。
  - 写入改为“临时文件 + fsync + 重命名”的原子落盘，进程中断不会留下半截 JSON。
  - 批量测速从“每个节点一次全文件读改写”收敛为“一次快照 + 一次原子保存”，大订阅下 I/O 从 O(N²) 降为 O(N)。
  - 延迟测试结果通过存储层原子合并接口落盘，避免与订阅更新互相覆盖。

- 核心生命周期并发收敛
  - 核心的启动/停止/重启全部经 `coreOpMu` 串行化，API 触发与看门狗重启不再互相踩踏。
  - 修复一个潜在自死锁：核心启动阶段意外退出时，清理逻辑不再重入生命周期锁。
  - 核心异常退出后，若自动重启失败，TUN 默认路由恢复与系统代理清理保证执行，机器不会残留“没有默认路由”的状态。
  - 意外退出清理移到锁外执行（不再持有服务互斥锁跑子进程）。

- 订阅自动更新
  - 新增自动更新调度：启用 `autoUpdateMinutes` 后按周期刷新订阅节点。
  - 失败退避 10 分钟，且退避记录持久化到 state，服务重启后不会立刻重打坏链接。

- TUN 策略路由清理优化
  - `ip rule del` 从逐个优先级探测（最多 1000 次子进程调用）改为枚举现有规则后精确删除。

- 移除无用配置
  - 删除已无意义的 `xrayCmd` 配置键和启动参数，核心引擎统一由 `coreEngine` 决定。

## 对用户的直接影响

- 状态轮询、批量测速和大订阅场景下的磁盘 I/O 与延迟明显下降。
- 核心崩溃后的自动重启更可靠：不会再出现“重启失败导致默认路由丢失”的残留状态。
- 订阅开启自动更新后，节点列表保持新鲜；坏订阅地址不会被反复请求。
- 版本升级不破坏现有数据：缓存与原子写对旧 JSON 文件完全兼容。
